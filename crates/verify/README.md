# frameever-verify: engine verification suite

Oracle tests for the playback, export, recording, editing and captions engines.
Fixtures are generated by code at test time. Every source video frame carries
its own identity as a block code, and every audio source carries
sample-accurate markers. An independent reference model computes which source
frame and sample each output frame and sample must show. A case passes only
when every checked frame and sample matches.

## Suites

The suites are listed in `scripts/verify/suites.json`. `scripts/verify/run.sh`
picks the ones for this OS and tier; a suite marked "any" tests
platform-independent logic and runs on every OS:

| Suite | What it checks | Windows | macOS |
| --- | --- | --- | --- |
| `verify-self` | marker codecs, reference model, report | fast | fast, full |
| `export` | every exported frame (MP4, GIF, both decoders on macOS) | fast, full | fast, full |
| `playback` | offline-driven editor playback frames | full | fast, full |
| `seek` | random, keyframe and scrub seeks | full | fast, full |
| `crash` | fragmented Studio recording under recorder and muxer kills, and recovery from what is on disk | fast, full | fast, full |
| `audio` | export and offline playback audio against sample-accurate markers | fast, full | fast, full |
| `editing` | random edit sequences exported and checked frame by frame | any | any |
| `captions` | fake-transcriber captions: segments and rendered captions on the right frames | any | any |
| `decoder-model-ffmpeg` | FFmpeg decoder decisions on scripted media (`frameever-rendering` `decoder::model`) | any | any |
| `chaos` | hostile device data, files, projects and settings: no panic, abort, signal, Objective-C exception, hang or wrong success | — | fast, full |
| `decoder-model-avf` | AVAssetReader decoder decisions on scripted media | — | fast, full |
| `native-rendering` | native macOS rendering regressions in the YUV converter | — | fast, full |

The app-level caption tests
(`apps/desktop-gpui/src/transcription/verify_tests.rs`: a fake transcriber
behind the real extraction and caption pipeline) live in the GPUI app's own
workspace and run inside `cargo test --bin frameever-gpui`. Run them with
`cargo test --manifest-path apps/desktop-gpui/Cargo.toml --bin frameever-gpui transcription::`.

`FRAMEEVER_VERIFY_TIER=full` (the FULL tier) uses longer fixtures and more seeds.

## Chaos suite

`crates/verify/tests/chaos.rs` tries to crash the engines. Every probe feeds one
hostile input to a product entry point and runs in its own child process (the
test binary re-run with `FRAMEEVER_VERIFY_CHAOS_CHILD`), so an abort, a fatal signal,
an Objective-C exception or a hang ends the child, not the run. A panic hook in
the child records every panic on any thread. Outcomes:

- `pass`: the engine returned an error, or it succeeded and its output checks
  out (readable media with packets when the input had usable frames).
- `panic`, `abort` (fatal signal or unexpected exit), `objc-exception`,
  `hang` (no verdict before the probe's timeout, reproduced once more) and
  `wrong-success` (success reported for an empty or unreadable output).

Areas, one test per area (`chaos_recording`, `chaos_files`, `chaos_export`,
`chaos_editor`, `chaos_fragments`, `chaos_fuzz`):

- `chaos/record/`: synthetic frames, audio buffers and control sequences
  through `OutputPipeline` with the Studio and Instant muxers (in-process and
  out-of-process on macOS), the microphone feed and source, the macOS camera
  conversion, and the Studio and Instant recording actors in camera-only mode
  with synthetic camera and microphone feeds, finalized like the app.
- `chaos/files/`, `chaos/export/`, `chaos/editor/`: a generated project with
  one damaged file, metadata or configuration field, opened like the editor's
  preflight, in `EditorInstance` (preview, playback, seeks) and exported;
  hostile export settings; non-finite values pushed in memory.
- `chaos/fragments/`: damaged fragmented recordings through crash recovery and
  Instant finalization.
- `chaos/fuzz/`: seeded fuzzing (structure-aware JSON, box-aware MP4 bytes).
  Each seed runs in a batch child; a crash or hang is pinned to its seed, and
  a failing seed is shrunk by dropping mutations while it fails the same way.
  The failure prints `FRAMEEVER_VERIFY_CHAOS_SEED` and `FRAMEEVER_VERIFY_CHAOS_KEEP` for
  its repro.

`FRAMEEVER_VERIFY_CHAOS_JOBS` sets the children run at once per test (default a
quarter of the cores, at most 3). `FRAMEEVER_VERIFY_CHAOS_KEEP_SCRATCH=1` keeps
each probe's scratch directory, child log and stderr.

## Running locally

```sh
scripts/verify/run.sh fast                    # the quick tier for this OS
scripts/verify/run.sh full                    # longer fixtures and more seeds
scripts/verify/run.sh fast --suites seek      # one suite
scripts/verify/run.sh fast --case 'export/basic/*'
scripts/verify/run.sh fast --list             # print the plan
```

Install cargo-nextest (`cargo install cargo-nextest --locked`) to run the
tests in parallel, one process per test. Without it, the script runs
`cargo test` per suite. The run uses the `dev` profile and shares its
build with normal development; `FRAMEEVER_VERIFY_CARGO_PROFILE=ci-verify` uses
the optimised `ci-verify` profile instead. Generated fixtures are cached in
`target/verify-fixtures`, or in `FRAMEEVER_VERIFY_FIXTURE_DIR` when it is set.

Every failure prints the exact frames or samples that are wrong, the seed,
and a one-line repro command, for example:

```sh
FRAMEEVER_VERIFY_CASE='export/backward-hold/backward-jumps/mp460/avf' FRAMEEVER_VERIFY_TIER=fast cargo test -p frameever-verify --test export -- --nocapture
FRAMEEVER_DECODER_MODEL_CASE=decoder-model/avf/syn/edlist/playback FRAMEEVER_DECODER_MODEL_SEED_INDEX=3 cargo test -p frameever-rendering --lib decoder::model::avassetreader_answers_match_the_reference_model -- --nocapture
```

## Known failures: strict expectations

Known bugs on `main` are strict expected failures. They are listed in
`crates/verify/expectations.toml` and in
`crates/rendering/src/decoder/model/expectations.toml`, using the format from
`crates/verify-expect`:

```toml
[[xfail]]
case = "export/early-camera/full/*"   # case id, * globs allowed
class = "future"                       # failure class that must still occur
platforms = ["macos"]                  # optional, absent = every platform
seeds = "0 3-7"                        # optional, seeded suites only
flaky = true                           # optional; state the measured rate
reason = "what is wrong"
link = "https://github.com/AniBullet/FrameEver/issues/<n>"  # empty = no fix yet
```

- A failure that is not listed fails the run.
- A listed class or seed that no longer fails also fails the run, with
  "remove this xfail". When a fix lands, its expected failures must be removed
  in the same PR, so the fix is locked in.
- A class that cannot be measured because an earlier check failed (A/V sync
  when no audio marker of a source could be identified) is recorded as "not
  measured", never as a pass: its xfail is neither confirmed nor reported as
  fixed, and bless leaves it alone. The failure that prevented the measurement
  is judged on its own, so it still has to be listed.

To update the files after a deliberate change, run:

```sh
scripts/verify/bless.sh fast              # run here and rewrite from the results
```

Bless changes only the entries of the platforms that ran. It keeps the
reasons and links of existing entries, and gives each new failure a `TODO:`
reason. Replace every `TODO:` reason before you merge. Review the diff: a
blessed failure is a bug that the suite keeps checking.

## Baseline comparison

Run `python3 scripts/verify/diff.py BASE_DIR MAIN_DIR --json comparison.json` over two report directories. Comma-separated run directories combine independent runs on each side. Keep both sides on the same OS image.

A required track absent from a recording leaves its dependent classes unobserved with reason `track absent`. A newly observed class appears in the coverage-gained column and is still judged by main's own expectations. Coverage gain alone is not an equal or worse result.

The `missing-after-hold` class measures an environment-sensitive ScreenCaptureKit idle-resume event. Compare at least three independent real-capture runs per side per OS image. A distribution is worse only when every main per-run count is above the baseline range. Insufficient repetitions and overlapping ranges are reported explicitly. Retries of one capture do not add independent samples. Other classes retain the strict zero-tolerance comparison.

Finalize crash cases hold the test muxer at entry to finalization after source EOF. The parent kills it while the barrier is held and checks that the recorder never wrote `done`. Missing the barrier or finding `done` is a harness failure. The barrier exists only in the integration-test wrapper and is disabled for all ordinary cases.
