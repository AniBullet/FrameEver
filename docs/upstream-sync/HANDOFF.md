### Compact main window (AniBullet/FrameEver#91, 2026-11-01)

`main_window/shell.rs` is the one state machine for the window: stages, the placements it asks for, what it remembers (`main_window` in `gpui-state.json`) and the Esc order, tested with events in and state and geometry out. Frames and the compact position are physical pixels with a scale beside them, and the expanded size and minimum sizes are logical, so a display at any scaling works without gpui's logical bounds. `platform/windows/main_frame.rs` carries it out. gpui fixes `is_resizable` and the minimum size when a window opens, so the main window opens resizable and a subclass makes compact fixed: it answers `WM_GETMINMAXINFO` and takes the resize edges out of `WM_NCHITTEST`. Client rectangles are what moves, because the custom frame's invisible border would otherwise shift the top-left. Win32 calls that resize run in a task, never with the App borrowed, or gpui's resize callback is lost with `RefCell already borrowed`. `main_window/surfaces.rs` draws the compact page and the library page. The existing grid sits inside the library with a Recordings and Screenshots switch; #92 replaces it. Fades are timed by hand because gpui's `with_animation` jumps to the end under reduced motion and the page keeps the fades. `Panel::Library` is gone, and the header's Screenshots, Recordings and bell buttons went with it; Changelog stays in Settings. Tab and Shift+Tab move focus in the main window only, because no window bound them before.

Collapsing returns to the compact position when the library wasn't moved and follows its top-left when it was. Close snaps to compact behind a hide; the tray's Open FrameEver, the recording picker shortcut and recording a new clip snap to compact directly. Other reasons to show the window keep its state. Settings hides the window only when compact, and collapsing while Settings is open hides it then. The tray's two View all rows became Open library. Alt+F4 and closing from the taskbar hide to the tray like the X, since the issue says close hides in both states; only the tray's Quit and a system shutdown end the app. Re-expanding to maximised is two native steps, restored frame then maximise, with nothing drawn between them. The tray's Open library and Open FrameEver, the close hide, Alt+F4, Ctrl+L, Esc, the remembered position, the light theme and the Tab order were checked in a dev build. ### Library grid (AniBullet/FrameEver#92, 2026-11-01)

`library/view.rs` is the view model: `build` turns entries, `ViewState`, the search text and the fresh projects into counts and sections, `rows` breaks those into list rows, and nothing in it needs a window. `ViewState` is `library` in `gpui-state.json`; search is not kept. `library::list_entries` scans every project, with folder sizes, durations from FFmpeg (cached in memory per file and mtime) and export file names. `main_window/library_page.rs` draws the page with gpui's virtualised `list`, decodes thumbnails only for rows that are drawn and keeps at most 600. `library/watch.rs` watches the known project folders without recursing, only while the library is showing, so it sees projects added, renamed or removed; a folder still being copied in, or a file deleted inside a project, shows up on the next focus rescan. Each change is a full rescan, kept cheap by the duration cache, rather than the incremental update #85 sketches. Tile meta keeps the clip count for multi-clip projects, which the design page does not show. The watcher lives inside its task, so keep its channel behind methods: a closure that names only the channel field drops the watcher at once. "Compressed copy only" needs a marker, so `delete_original` now writes `content/original_deleted`; originals deleted before this show as uncompressed.

New recordings go through `note_new_recording`: with the library open they go first and carry the tick and highlight for 6 seconds, otherwise they count on the compact window's Library badge and get the same treatment on the next expand. The first recording's line shows once (`library_first_line_shown`). Imports get their own rows at the top, and Import became a menu because the tabs no longer say which kind. The design page gained Import and lost the Ctrl+Shift+R hint on the empty library, because no shortcut is set by default. The incomplete recording toast still sits over the status bar until it is answered.

Checked in a dev build with the Chinese UI, dark and light: tabs, status menu, Import menu, search, no matches, Clear filters by Esc, keyboard reach, a project added and removed in the storage folder, and the tab surviving a restart. Not checked: a real new recording (tick, line, badge), 125 to 200%, and the owner's comparison with the design page.

### List view, selection and detail panel (AniBullet/FrameEver#93, 2026-11-01)

`view::Selection` holds paths, not indexes, so a rescan cannot move it; `step_from` walks the rows, `row_of` finds an item's row, and `ViewState::sort_by_column` is the column click. A click now only selects; Enter and double-click open, and the hover buttons on the thumbnail are gone. A double-click opens what the first click landed on, because that click may open the panel and reflow the grid. The panel takes 340 px off the columns whenever exactly one item is selected. Keys bound in the `LibraryItems` context work only while the items area has focus, so tiles are no longer tab stops: the area is one stop, the lead shows the ring and everything else is reached by Tab into the panel. List column heads sit outside that area so Enter sorts instead of opening. Rename changes `pretty_name` only, never the folder. The panel shows the still thumbnail until #95 brings the player, and Instant still opens its folder on Enter until #96. Export from the library opens the editor's export page for Studio, saves the PNG for a screenshot and copies the current video for Instant, which records it as an export. ### Delete, batch panel and compression queue (AniBullet/FrameEver#94, 2026-11-01)

### Library preview player (AniBullet/FrameEver#95, 2026-11-02)

`library/player.rs` is one light player, separate from the editor. `segments_of` says what an entry plays: Instant its `output.mp4`, Studio its latest export, otherwise each raw segment's `display.mp4` with its microphone and system audio mixed, each track offset by its `start_time` against the display's. Several segments play as one timeline (`player/timeline.rs`). Video and audio each open the file themselves, on their own threads, so a badly interleaved file can't deadlock them: `player/video.rs` decodes in software and scales to BGRA at the box's physical size, `player/audio.rs` decodes and resamples to the device format and feeds a two-second buffer read by the cpal callback. The callback sets `player/clock.rs`, which runs on for at most 60 ms between ticks, so an underrun stops the picture rather than letting it run ahead. With no audio track, no device or a stream error the clock follows the wall. Pacing is `video::pace`, and `player/timer.rs` holds `timeBeginPeriod(1)` while playing, because without it frames land on 15.6 ms boundaries. `Player::take_frame` is a latest-wins slot, so a busy UI thread skips frames rather than queueing them, and each frame the page replaces goes through `window.drop_image`.

Nothing opens until Play or a seek, so arrowing through the library costs nothing. Selecting another item, a new export, collapsing or a version switch stops the player. `player::release(project)` stops any player on a project and waits for its files, and every path that moves or deletes project files calls it, in `versions.rs` and `library.rs`, so automatic compression and Settings can't hit a file in use; the page learns about it when the event channel closes. Recording starting and opening an item pause it, and pausing keeps the decoder. Reduced motion has nothing to change here.

The page side is `main_window/library_page/preview.rs`. The player sits in `MainWindow` rather than its own entity, because a child's notify marks its ancestors dirty and `MainWindow::render` would run anyway. Each frame therefore renders the page; in a debug build this kept up. Failure replaces the stage with what happened, what to do next and Try again; the design page gained that state. Play, the slider and Mute are tab stops, and on the slider left and right move 5 seconds, Home and End go to the ends. `FRAMEEVER_GPUI_AUTO_LIBRARY_PLAY=<seconds>[:<name>]` plays through the same handlers in a debug build and logs `library preview playback`.

Measured on the issue, on the owner's machine in a debug build, with a 1080p60 H.264 clip that flashes and beeps once a second: `FRAMEEVER_PLAYER_FILE=<clip> RUST_TEST_NOCAPTURE=1 pnpm fe test measure_frame_timing`. Picture and sound agree to about 3 ms once the clip's own beep timing is taken out. That figure trusts the latency WASAPI reports; nothing measured sound leaving the speakers. Full-screen 60 fps is still unmeasured and belongs to #96.

Left as they are: a file that goes bad partway keeps the last good frame and runs out the clock, because a static screen recording can have long gaps between frames, so there is nothing reliable to tell them apart. Decoding is full resolution in software with swscale shrinking each frame, so a 4K60 source held 60 fps but costs CPU; D3D11VA is the next step if that shows up. The first few frames after Play can stall about 80 ms while the audio device starts. Checked in a dev build with the Chinese UI, dark: playback through the page and the failed state, both by capturing the window. Not checked: mouse on the slider, the keyboard path, light theme, 125 to 200%, hearing sound, a Studio project with real microphone and system audio, and multi-segment audio by ear; the owner checks these with the design page.
