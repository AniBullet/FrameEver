### Library preview player (AniBullet/FrameEver#95, 2026-11-02)

`library/player.rs` is one light player, separate from the editor. `segments_of` says what an entry plays: Instant its `output.mp4`, Studio its latest export, otherwise each raw segment's `display.mp4` with its microphone and system audio mixed, each track offset by its `start_time` against the display's. Video and audio each open the file themselves, on their own threads, so a badly interleaved file can't deadlock them: `player/video.rs` decodes in software and scales to BGRA at the box's physical size, `player/audio.rs` decodes and resamples to the device format and feeds a two-second buffer read by the cpal callback. The callback sets `player/clock.rs`, which runs on for at most 60 ms between ticks, so an underrun stops the picture rather than letting it run ahead. With no audio track, no device or a stream error the clock follows the wall. Pacing is `video::pace`, and `player/timer.rs` holds `timeBeginPeriod(1)` while playing, because without it frames land on 15.6 ms boundaries. `Player::take_frame` is a latest-wins slot, so a busy UI thread skips frames rather than queueing them, and each frame the page replaces goes through `window.drop_image`.

Nothing opens until Play or a seek, so arrowing through the library costs nothing. Selecting another item, a new export, collapsing or a version switch stops the player. `player::release(project)` stops any player on a project and waits for its files, and every path that moves or deletes project files calls it, in `versions.rs` and `library.rs`, so automatic compression and Settings can't hit a file in use; the page learns about it when the event channel closes. The player sits in `MainWindow` rather than its own entity, because a child's notify marks its ancestors dirty and `MainWindow::render` would run anyway. Play, the slider and Mute are tab stops, and on the slider left and right move 5 seconds, Home and End go to the ends. `FRAMEEVER_GPUI_AUTO_LIBRARY_PLAY=<seconds>[:<name>]` plays through the same handlers in a debug build and logs `library preview playback`.

Full-screen 60 fps is still unmeasured and belongs to #96.
