# App icon and brand colours

All brand assets are generated by `apps/desktop-gpui/packaging/brand/render_brand.py`: the Windows icon set, PNGs, tray icon, in-app logo layers, the SVG source and the installer images. Colours and geometry are constants at the top of that script; change them there and rerun it (`python packaging/brand/render_brand.py .` from `apps/desktop-gpui`, after `pnpm fe setup` so the fonts exist).

## Core colour

Klein blue `#1F3FD8`, chosen by the owner on 2026-10-24 from thirteen candidates. The record button must stay red so the icon reads as a recorder (like the iOS screen-recording control).

## Record button

iOS structure: white ring (radius 9.5 on the 48 grid), a navy gap (`#000F5C`, radius 7.6), a red dot (radius 6.1). The navy gap lifts the dot's contrast from 2.3 (red on blue) to 5.3. Below 24 px the gap is dropped and the dot sits directly in the ring.

## How we got here (so it is not repeated)

Contrast-first choices (plum, a Material 3 palette seeded with the old mint) met every number and still looked wrong, and a black plate vanished on dark taskbars. What worked: the owner picks a core colour first from a wide set of options, then the palette comes from established, designer-shared combinations for that colour, and contrast is only a final check.

## Where it is used

- Windows icon `icons/icon.ico` (16–256 px, 15 frames; 16, 20 and 24 are drawn pixel by pixel, the rest are rendered from the vector shapes), PNGs, `assets/dock-icon.png`.
- In-app logo: single-colour SVG layers `assets/icons/logo-*.svg`, composed in `src/logo.rs`; the plate shows in both themes.
- Installer: `packaging/windows/nsis-sidebar.bmp` (light surface, icon, left-aligned type, a short brand-blue rule) and `nsis-header.bmp`, both at 2× so they stay sharp on scaled displays. The Chinese installer uses Microsoft YaHei UI.
- The window icon is loaded from `icon.ico` at the taskbar's size (24 logical px × display scale) and the small icon at the system small-icon size (`platform::apply_app_icon`); the tray icon is loaded from `icon.ico` at the system small-icon size (`tray::windows::app_tray_icon`). Windows picks the exact frame, so nothing is rescaled.
